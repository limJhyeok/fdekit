# 제출 전 체크리스트

종료 10분 전에는 제출을 시작한다. 아래 순서로 확인하고, 실패한 항목은 고치거나 README에 적는다.

## 실행
- [ ] 저장소를 새로 받은 상태(새 디렉터리에 clone)에서 README의 명령 하나로 서버가 뜬다
- [ ] 기본 경로(`/`)가 열린다
- [ ] 필수 요구사항의 S1 시나리오를 화면에서 한 번씩 통과한다

## 테스트
- [ ] 테스트 전체를 실행해 통과했다 (실행 명령과 결과를 기록)
- [ ] 마지막 테스트 통과 뒤에 코드를 크게 바꾸지 않았다. 바꿨다면 다시 실행했다
- [ ] ACCEPTANCE.md '확인 결과 기록'이 실제 확인 결과와 맞다

## 보안·제약
- [ ] 코드와 git 기록에 키가 없다 (예: `git log -p | grep -iE "sk-|api_key"`)
- [ ] `.env`가 `.gitignore`에 있고 커밋되지 않았다
- [ ] 저장하면 안 되는 데이터(제약 C-ID)가 디스크·DB·로그에 남지 않는다

## 문서
- [ ] README: 실행 방법 / 요구사항 ID ↔ 기능 / 합의한 범위와 하지 않은 것(이유) / 기본 가정·미확정 / DECISIONS.md 링크
- [ ] 문서에 있는데 구현되지 않은 기능이 없다 (있으면 지우거나 "미구현"으로 표시)
- [ ] `DECISIONS.md`의 구체값(버전, 모델 이름, 포트, 실행 명령)이 실제 실행과 맞다. 예: 적어 둔 Python 버전과 `.venv/bin/python --version`
- [ ] `[미확정]`이 남은 시나리오는 README의 미확정 목록에 있다
- [ ] `WEAKPOINTS.md` 카드가 최종 코드와 맞는다. 마지막 커밋들이 바꾼 동작을 반영했다. 제출 직전에 5분 동안 전체를 다시 읽는다

## git
- [ ] 커밋되지 않은 변경이 없다
- [ ] 커밋 메시지에 요구사항 ID가 들어 있다
