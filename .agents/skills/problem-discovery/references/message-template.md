# 문의 메시지 (partner-message.md)

노트의 질문 리스트를 현업 담당자가 바로 답할 수 있는 업무용 챗 메시지로 바꾼다.
한 통에 모든 질문을 담지 않는다. **첫 메시지**와 **차수별 질문 계획**으로 나눈다.

## 작성 규칙
- **담당자에 맞춘 언어를 쓴다.** 노트의 이해관계자 표에 적은 담당자의 기술 배경을 따른다.
  - **기본(비개발자이거나 배경을 모를 때): 비개발자 언어만 쓴다.** API, 데이터베이스, 검색 방식, 모델 같은 기술 용어를 넣지 않고 업무 장면으로 묻는다. 기술 선택은 묻지 않고 응시자가 정한다.
  - **예외(담당자가 개발자·기술 결정권자임이 문제 설명이나 대화에 [사실]로 드러날 때):** 기술 용어를 써도 되고, 기술 제약(사용 가능한 스택, 연동 대상, 배포 환경 등)을 물어도 된다. 직함만 보고 추정하지 않는다. "개발팀장"처럼 보여도 문서·대화에 근거가 없으면 기본 규칙을 따른다.
  - 예외일 때도 **업무 맥락을 먼저** 묻는다. 담당자가 개발자여도 요구사항의 출발점은 사용자와 업무 장면이다. 기술 질문이 업무 질문을 밀어내지 않게 한다.
- **한 번에 1~3개만 묻는다.** 질문 하나에는 한 가지만 묻는다. 번호를 붙여 어느 질문에 답했는지 추적할 수 있게 한다.
- **노트 질문을 옮길 때 빠뜨리지 않는다.** 노트의 한 질문이 두 가지를 묻고 있으면 메시지 질문 두 개로 나누거나, 한쪽을 다음 차수로 미뤘다고 응시자용 메모에 적는다. 조용히 사라지는 질문이 없어야 한다.
- **질문 방식(노트의 질문 방식 열)에 맞춰 문장을 만든다.**
  - 열린 질문: 자료에 단서가 없는 것. 근거 없는 선택지를 깔지 않는다. 선택지가 필요하면 "기타"를 넣는다.
  - 해석 확인: "<파일·항목> '<인용>'을 <내 해석>으로 이해했는데 맞을까요?"
  - 값 인용: "<파일·항목>에는 <값>으로 되어 있는데 지금도 그대로인가요?"
  - 사례: "최근에 <상황>이 있었을 때 어떻게 처리하셨어요?"
- **기본값을 함께 보여 줄 때도 선택지는 빠짐없이 둔다.** 시간이 부족하면 "(답이 어려우시면 ~로 진행하겠습니다)"처럼 기본값을 괄호로 붙여도 된다. 다만 선택지가 둘이면 "둘 다"나 "기타"를 넣는다. 기본값만 보이면 담당자가 그대로 동의하기 쉽다.
- **파일명과 항목 번호를 인용한다.** 상대가 문서를 열지 않아도 답할 수 있게 한다.
- **민감한 확인은 부드럽게 바꾼다.** 예: 요청 발화자 확인 → "말씀 주신 기준은 <호칭>님께서 지키시는 기준인가요?"
- **"다 알려 주세요"류 질문을 하지 않는다.** "필요한 걸 모두 알려 주세요", "어떻게 하면 될까요?"는 답하기 어렵고 정보도 적게 나온다.

## 차수 나누기
노트의 질문을 아래 순서로 묶는다. 앞 차수의 답에 따라 뒤 차수 질문이 바뀔 수 있으므로, 2차 이후는 **계획**으로만 둔다.

| 차수 | 담을 질문 | 이유 |
|---|---|---|
| 1차 | 사용자·사용 장면, 가장 중요한 업무 기준, 상호작용 형태 | 이후 모든 판단의 전제 |
| 2차 | 업무 기준 일반화, 입력 방식에서 생기는 기준, 우선순위(가장 많은 일, 잘못되면 가장 곤란한 일), 요청 핵심 표현의 범위 | 결과물의 핵심 동작과 범위를 정하는 근거 |
| 3차 | 제약(저장·개인정보·금지사항·보안), 문서에 없는 경우의 대응 | 먼저 말해 주지 않는 주제 |
| 4차 | 자료 해석 확인, 값 인용 확인 | 짧게 끝나는 확인 질문 |
| 5차 | 문서 관리(최신본, 변경 주기, 관리 주체) | 영향이 가장 작음 |

## 형식

```markdown
## 첫 메시지 (지금 보낼 것)

안녕하세요 <호칭>님, <과제 한 줄> 맡은 <이름>입니다.
받은 <자료 목록>을 먼저 읽어 보았고, <목적>을 위해 몇 가지 여쭙겠습니다. 짧게 답 주셔도 충분합니다.

1. ...
2. ...
3. ...

## 이후 질문 계획 (답을 받은 뒤 다듬어 보낼 것)

### 2차: <주제>
4. ...

### 3차: <주제>
...

---
## 응시자용 메모 (담당자에게 보내지 않음)
| 메시지 질문 번호 | 노트 질문 번호 | 질문 방식 | 비고(합치거나 바꿔 쓴 이유) |
|---|---|---|---|
```
