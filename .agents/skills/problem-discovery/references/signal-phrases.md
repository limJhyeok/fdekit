# 문제 설명에서 자주 나오는 신호 표현

해석은 [추정]으로 기록한다. 이 표의 해석을 [사실]로 쓰지 않는다.

| 표현 | 가능한 의미 |
|---|---|
| "아직 정리하지 못했다", "대화를 통해 발견하라" | 요구사항을 찾아내는 과정 자체가 과제의 핵심 |
| "모든 필요를 구현할 필요는 없다", "범위를 합의" | 범위를 줄이고 그 이유를 합의하는 과정이 요구됨 |
| "~도 과제의 일부입니다" | 문서가 직접 평가 대상이라고 밝힌 활동. 이 표현이 붙은 것만 평가 대상으로 표시 |
| "별도 설명 없이 사용할 수 있는" | 사용성이 요구사항 |
| "키를 코드에 쓰지 마세요", "커밋하지 마세요" | 반드시 지킬 보안 제약 |
| "사람마다 다르다", "일관성이 없다" | 기준이 공유되지 않았거나 자료끼리 차이가 있을 수 있음. 원인은 단정하지 말 것 |
| "일단 ~해 볼 수 있으면" | 완성도보다 시범 사용이 우선일 수 있음 |
| "제가 ~할 때 지키는 기준" | 발화자의 암묵지. 발화자가 누구인지 문서에 명시되었는지 확인 |
| "응시자 판단에 맡깁니다" | 자유도. 선택한 이유를 나중에 설명할 수 있어야 함 |
| "API, 저장 방식, 화면 수는 정해 주지 않습니다" | 현업에게 기술 질문을 하지 말라는 신호. 업무 장면으로 질문할 것 |
