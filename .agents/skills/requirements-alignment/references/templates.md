# 파일 형식

## conversation-log.md

```markdown
# 현업 대화 기록
담당자: <이름, 역할>

## 1차 (<날짜>)
### 보낸 메시지
> <원문 그대로>

### 받은 답변
- #1-1 > <답변 첫 문단 원문>
- #1-2 > <답변 둘째 문단 원문>

### 판정
| 질문 | 노트 질문 # | 판정 | 비고 |
|---|---|---|---|
| 1 | Q3 | 답함 / 일부 답함 / 답 없음 / 모름 | <빠진 부분, 새 정보> |

### 자료와 다른 점
- 자료: <파일·항목> "<값>" / 담당자: #1-2 "<값>" / 현재 유효: <담당자가 말한 쪽, 미확인이면 "확인 필요">

### 범위가 좁혀진 답
- #1-2 "그 사례에서는 …" → 다음 차수 일반화 질문: <질문>

### 멈추기 전 점검
| 요청 핵심 표현 / 핵심 동작 | 근거 대화 # | 상태 (답함 / 사례 하나뿐 / 없음) |
|---|---|---|
```

## requirements.md

```markdown
# 요구사항

## 요구사항 목록
| ID | 요구사항 (사용자가 할 수 있어야 하는 일) | 근거 | 중요도 | 중요도 이유 | 합격 조건·확인 방법 | 관련 기준 |
|---|---|---|---|---|---|---|
| R1 | | 대화 #n-m / <파일·항목> | 필수 / 권장 / 이후 | | | B1 / C2 / — |

## 업무 기준 (결과물이 지켜야 할 규칙)
| ID | 기준 | 적용 대상 R-ID | 합격 조건 | 확인 방법 (수치면 입력·환경·측정 방식 포함) | 근거·상태 |
|---|---|---|---|---|---|
| B1 | | R1 | | | 대화 #n-m / <파일·항목> / 기본 가정 / 미확인 |

## 제약
| ID | 제약 | 적용 대상 R-ID | 합격 조건·확인 방법 (확인 가능할 때) | 근거·상태 |
|---|---|---|---|---|
| C1 | 작업 시간: 문제 설명 <n>시간 / 실제 <m>시간(사용자 안내) — 실제 시간 기준 | 전체 | 확인 불가 | 문제 설명, 사용자 |
| C2 | | R1 / 전체 | | |

## 제안 (근거 없음 — 담당자 확인 전)
- <응시자 아이디어. 범위 제안 때 함께 물어볼 것>

## 기본 가정으로 처리한 것
| 노트 질문 # | 가정 | 가정의 근거 | 담당자 상태 (미질문 / 모름) |
|---|---|---|---|

## 범위 제안
- 이번에 할 것: R1, R2, ... (적용 B-ID·C-ID와 제안한 합격 조건 포함)
- 이번에 하지 않을 것: R5(이유), ...

## 합의 기록
- <차수> 대화 #n-m > "<담당자 동의 문장 원문>"
- 조정 내역: <처음 제안 → 바뀐 내용, 이유>
```
