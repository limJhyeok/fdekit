# HANDOFF.md 형식

읽는 사람은 다음 개발자다. 담당자 맥락을 모르고, 대화 기록을 처음부터 읽을 시간이 없다고 가정한다.
문장은 짧게, 주장마다 근거 번호를 단다. 표로 쓸 수 있으면 표로 쓴다.

```markdown
# 인수인계 (HANDOFF)

> 작성: <YYYY-MM-DD>, <시점: 첫 시연판 제출 / 중간 인계 등> (커밋 `<short hash>` 기준)
> 담당자: <이름>, <소속·역할> (<개발자 여부. 담당자가 정하지 않는 것: 예) API·저장 방식·화면 수>)
> 근거 번호 `#n-m`은 [conversation-log.md](conversation-log.md)의 대화 번호, R·B·C·Q는 [requirements.md](requirements.md), D는 [DECISIONS.md](DECISIONS.md), 시나리오 ID는 [ACCEPTANCE.md](ACCEPTANCE.md)

이 문서는 다음 개발자가 바로 이어서 작업할 수 있도록 "지금 어디까지 왔고, 무엇을 지켜야 하고, 무엇이 위험한가"를 모은 것입니다. 실행 방법과 기능 대응표는 [README.md](README.md)에 있습니다.

---
```

## 쓰는 규칙
- **"확인 완료"는 테스트나 화면에서 직접 확인한 것만.** 테스트가 키 없이 건너뛰었으면 확인 완료가 아니다.
- **담당자 말은 인용부호 안에 원문 그대로.** 요약할 때는 인용부호를 쓰지 않는다.
- **상태 표현은 담당자가 한 말까지만.** "확인이 필요하다"고 했으면 "확인 중", "알려 주기로 함"으로 쓰지 않는다.
- **숫자는 도구로 센 값.** 테스트 개수, 시간, 버전, 호출 횟수.
- **영향 칸에는 부딪치는 제약 ID를 쓴다.** 다음 사람이 "기록 남기기"처럼 쉬워 보이는 요청을 받았을 때 제약 위반을 바로 알아보게 하기 위해서다.
- **6절은 겪은 일만.** "테스트를 자주 돌리세요" 같은 일반론은 쓰지 않는다. 사례가 없으면 그 소제목을 지운다.
- 문체는 같은 저장소의 다른 문서(README 등)에 맞춘다.
