# HANDOFF 자기 검토 패턴

저장 전에 각 문장을 근거(대화 원문, 테스트 출력, 코드)와 나란히 놓고 아래 패턴에 걸리는지 본다.
각 예시는 다른 업종의 가상 과제다.

## 1. 담당자 상태 표현을 앞으로 나간 것처럼 씀
- **원문:** "외부 업체에 자료를 보내도 되는지는 확인이 필요한 사항이에요." (#4-2)
- **잘못 쓴 문장:** "외부 전송 허용 여부는 담당자가 확인 중이며 회신 예정."
- **왜 문제인가:** 담당자는 확인하겠다고도, 알려 주겠다고도 하지 않았다. 다음 사람이 답을 기다리며 일을 멈춘다.
- **고친 문장:** "외부 전송 허용 여부: 담당자 표현은 '확인이 필요한 사항'(#4-2). 그전까지는 내부 처리만 하기로 합의(#5-1)."

## 2. 반대가 없었던 것을 동의로 씀
- **원문:** 작업자 메시지 "합계가 0인 주문은 이상 건으로 보지 않겠습니다." → 담당자 답에 이 내용 언급 없음
- **잘못 쓴 문장:** "합계 0 주문은 이상 건이 아님 [합의]"
- **고친 문장:** "합계 0 주문은 이상 건으로 보지 않음. 7차 메시지로 알렸고 반대는 없었지만, 동의를 받은 것은 아님 (3-1)"

## 3. 확인하지 않은 것을 "확인 완료"로 씀
- **상황:** API 키가 없어 LLM 테스트 12개가 건너뜀
- **잘못 쓴 문장:** "전체 테스트 통과 (40개)"
- **고친 문장:** "28개 통과, 12개 건너뜀(키 없음). 요약 판정(R3)은 키 있는 환경에서 확인하지 않음"

## 4. 합의되지 않은 후보를 현재 범위처럼 씀
- **원문:** "나중에는 상담 이력도 보면 좋겠네요." (#9-1)
- **잘못 쓴 문장(1절):** "상담 이력 보기는 다음 단계에서 구현 예정"
- **고친 문장(2절 표):** 후보 "상담 이력 보기" / 담당자 말 "나중에는 상담 이력도 보면 좋겠네요"(#9-1) / 협의할 점: 언제, 누가 볼지 / 영향: **저장 금지 제약(C3)과 부딪침**

## 5. 재현하지 않은 문제를 단정함
- **잘못 쓴 문장:** "파일이 크면 서버가 멈춘다."
- **고친 문장:** "본문을 다 읽은 뒤 크기를 검사함(코드 확인). 아주 큰 요청으로 메모리를 소모시킬 수 있음. 재현하지 않음"

## 6. 일반론으로 6절을 채움
- **잘못 쓴 문장:** "변경 후에는 테스트를 꼭 실행하세요."
- **왜 문제인가:** 누구나 아는 말이라 읽히지 않는다. 겪은 사례가 붙어야 다음 사람이 지킨다.
- **고친 문장:** "판정 규칙 한 줄을 바꿨더니 다른 시나리오 테스트 3개가 깨졌습니다(16차 반영 때). 바꾼 시나리오만 돌리지 말고 전체 테스트를 돌리세요."

## 7. 없는 이름을 씀
- 문서에 적은 파일·함수·상수·환경변수·테스트 이름을 `grep`으로 찾는다. 이름을 바꾼 뒤 문서를 고치지 않은 경우가 많다.

## 8. architecture.md와 현재 구현이 어긋남
- 그림의 구성요소·화살표·저장 위치·외부 전송 조건을 실행 진입점과 실제 호출 코드에 대어 확인한다.
- 형식만 검사하는 코드를 결과의 의미적 정확성까지 보장한다고 쓰지 않는다.
- HANDOFF에는 architecture.md 링크를 두고, 변경 위험이 큰 진입점만 요약한다. 두 문서에서 서로 다른 실행 흐름을 설명하지 않는다.
