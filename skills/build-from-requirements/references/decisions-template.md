# DECISIONS.md 형식

결정은 짧게, 이유는 요구사항·제약 ID로. 나중에 "왜 이렇게 했나"에 이 파일 하나로 답할 수 있어야 한다.

```markdown
# 설계 결정

| ID | 결정 | 이유 (근거 ID) | 대안과 버린 이유 | 되돌리는 비용 |
|---|---|---|---|---|
| D1 | <기술 스택> | 사용자 요청에 따르면 ...(R2), 시간 제약(C1) | <대안>: <이유> | 큼 |
| D2 | <화면 흐름: 시작 → 입력 → 결과 → 다시 하기> | 설명 없이 사용(R6), 다시 연습(R8) | | 중간 |
| D3 | <저장하지 않는 것> | <제약 ID> | | 큼 |
| D4 | <LLM을 쓰는 지점과 결과 형식> | <R-ID, B-ID> | | 중간 |
| D5 | <[미확정] 항목을 이렇게 처리> | 담당자 답 없음(대화 #n-m에 질문), 기본 가정 | <다른 선택지> | |

## 미확정 → 결정으로 바꾼 것
- <ACCEPTANCE 시나리오 ID>: <무엇을 어떻게 정했나>. 담당자에게 알림: <예정 / 대화 #n-m에서 알림>
```

- 버전·모델 이름·포트처럼 **구체값**을 적으면 이유 칸에 출처를 단다(예: "`python3 --version` 결과", "문제 설명 '실행 환경'"). 출처 없이 고른 값이면 고른 이유를 쓴다. 실행 스크립트가 다른 값을 고를 수 있으면(예: 가상환경 도구가 다른 버전을 설치함) 실제로 쓰이는 값을 확인해서 적는다.
- 결정이 바뀌면 행을 지우지 말고 "D2 → D2a로 대체 (이유)"처럼 남긴다.
- 되돌리는 비용이 "큼"인 결정은 1-3 단계에서 사용자에게 한 번 더 보여 준다.
