# 범용 채점 프롬프트

실제 시험 채점자는 이 스킬의 4칸 틀, 모범 답안의 칸 구분, "문장력이 아니라 내용" 같은 우리 쪽 기준을 모를 수 있다.
그런 채점자가 답만 보고 어떻게 읽는지 확인한다. 칸별 채점(`grading-rubric.md`)보다 낮게 나오면 그 차이가 **형식 때문에 생긴 손해**다.

새 컨텍스트(서브에이전트)에 아래를 그대로 보낸다. `<...>`만 채운다.
- 넘기는 것: 질문 원문과 사용자 답 원문뿐이다. 모범 답안, `sub_questions`, 코드, 답안 틀, 칸별 채점 결과는 넘기지 않는다. 넘기면 범용 채점이 아니게 된다.
- 사용자 답은 고치지 않고 그대로 넘긴다(오타, 번호, 화살표 포함).
- 모든 문항을 한 번에 보낸다.

```text
너는 서술형 시험 채점자다. 응시자는 자기가 만든 소프트웨어에 대한 질문에, 문항당 5분 안에 코드를 보지 않고 타이핑해 답했다.
너는 그 소프트웨어의 코드를 볼 수 없다. 답의 사실 여부는 판단하지 말고, 답이 질문에 답하고 있는지와 읽는 사람이 그것을 알아볼 수 있는지만 본다.

문항마다:
1. 질문을 하위 질문으로 나눈다 (질문이 실제로 묻는 것만, 최대 3개).
2. 하위 질문마다
   - verdict: answered(답했고 어느 부분이 답인지 분명함) / unclear(답한 것 같지만 어느 부분이 답인지, 또는 무슨 뜻인지 추측해야 함) / not_answered
   - located: 그 답이라고 본 부분을 응시자 답에서 그대로 인용. 없으면 null
   - reason: unclear·not_answered면 왜 그렇게 봤는지 한 문장
3. score: 0~10 (질문에 대한 답으로서의 완성도)
4. hard_to_read: 읽기 어렵거나 뜻이 두 가지로 읽히는 표현을 인용과 함께 최대 3개 (기호의 뜻, 주어 없는 구절, 질문과 연결되지 않는 줄 등). 없으면 빈 목록

<기록 위치>/generic-grade.json 에 쓴다:
{"questions":[{"id":"Q1","sub_questions":[{"text":"...","verdict":"answered","located":"...","reason":null}],"score":7,"hard_to_read":[{"quote":"...","why":"..."}]}]}

마지막 응답에는 "작성 완료"만 쓴다.

[문항]
## Q1
질문: <질문 원문>
답:
<사용자 답 원문>

## Q2
...
```

## 결과 비교 (메인 에이전트)
문항마다 범용 채점의 하위 질문을 answer-key의 `sub_questions`와 짝짓고, 칸별 채점과 나란히 본다.

| 칸별 채점 (내용) | 범용 채점 | 판단 |
|---|---|---|
| met / partial | answered | 문제 없음 |
| met / partial | unclear · not_answered | **형식 손해.** 내용은 있는데 채점자가 못 찾거나 잘못 읽음. 해설에 원인(라벨 없음, 판단형인데 판단 줄 없음, `→` 뜻이 모호함 등)과 고친 줄을 단다 |
| missed | answered | 범용 채점자가 그럴듯한 일반론에 속은 것. 내용 해설로 충분하다. 형식 문제로 다루지 않는다 |
| missed | unclear · not_answered | 내용 문제. 내용 해설로 충분하다 |

- 범용 점수(0~10)는 칸별 판정과 척도가 달라 직접 빼지 않는다. 회차 사이의 추이만 본다.
- `hard_to_read`는 형식 손해가 난 문항에서만 해설에 옮긴다.
