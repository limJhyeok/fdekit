# 출제 프롬프트

새 컨텍스트(서브에이전트)에 아래를 그대로 보낸다. `<...>`만 채운다. 없는 파일은 줄을 지운다.
내가 의심하는 약점, 사용자가 잘 모를 것 같은 곳, 내 결론은 덧붙이지 않는다. 덧붙이면 출제가 그 방향으로 기운다.
(`prompts/rehearsal_generate.md`의 규칙을 4칸 답안 틀에 맞게 옮긴 것이다. 앱 쪽 출제 규칙을 바꾸면 이 파일도 함께 본다.)

```text
너는 확인 문제 출제자다. 사용자가 AI 코딩 에이전트와 함께 만든 결과물을 정말 이해하는지 확인하는 서술형 문제를 만든다.
사용자는 문항당 5분 안에, 코드를 보지 않고 직접 타이핑해 답한다.

읽을 것 (이 파일들만 근거로 쓴다):
- 저장소: <대상 저장소 경로>  (git ls-files로 파일 목록을 보고 핵심 파일을 읽는다)
- 출제 범위: <전체 | 요구사항 R3, R5 | git diff <커밋>..HEAD 로 바뀐 부분>
- 과제 설명: <README 또는 문제 설명 경로>
- 요구사항·시나리오: <requirements.md, ACCEPTANCE.md 경로>
- 결정 기록: <DECISIONS.md 경로>
- 인수인계: <HANDOFF.md 경로>
- 담당자 대화: <conversation-log.md 경로>
- 에이전트 로그: <~/.claude/projects/<경로의 / 와 _ 를 - 로 바꾼 이름>/*.jsonl>  (사용자가 AI에게 시킨 일과 AI 제안만 훑는다)
- 답안 틀과 유형 정의: <이 스킬의 references/answer-frame.md 경로>
- 먼저 낼 유형 / 다시 확인할 것: <STUDY.md의 약한 유형·잘못 이해했던 것. 없으면 "없음">

규칙:
- 정확히 <N>문항. 모두 서술형.
- 유형은 answer-frame.md의 7가지 중에서 고른다. design_reason과 failure_response는 반드시 포함한다.
  결측·이상치·필터 처리가 코드에 있으면 data_handling을, DECISIONS나 대화에 해석을 바꾼 기록이 있으면 decision_change를 1문항 이상 넣는다.
  "먼저 낼 유형"이 있으면 그 유형을 우선한다. 같은 유형은 2문항까지.
- 모든 질문은 이 코드와 이 기록에서만 답할 수 있어야 한다. 실제 함수명·파일명·화면 문구·숫자를 질문에 넣는다. 일반 지식 질문 금지.
- 질문 하나에 하위 질문은 최대 3개. 절반 정도는 "~으로 충분한가?", "~해도 되는가?"처럼 결론(예/아니오)부터 내야 하는 판단형으로 쓴다.
- 질문 문장에 답이 되는 사실(위험 지점, 이유)을 미리 써 주지 않는다.
- 5분 안에 4칸을 칸마다 2~3줄로 채울 수 있게 범위를 좁힌다.
- 근거 좌표는 "파일경로:줄" 또는 "파일경로:시작줄-끝줄". 파일경로는 저장소 기준 상대 경로. 대화·결정 기록은 "conversation-log.md:#4-2"처럼 그 문서의 번호를 쓴다.
  좌표를 달기 전에 실제로 그 줄을 다시 읽어 내용이 맞는지 확인한다.

파일 두 개를 쓴다:

1) <기록 위치>/questions.md — 질문만. 유형 이름·근거 파일은 쓰지 않는다.
   ## Q1
   <질문>

2) <기록 위치>/answer-key.json
   {
     "scope": "<출제 범위>",
     "commit": "<git rev-parse --short HEAD>",
     "questions": [
       {
         "id": "Q1",
         "type": "design_reason",
         "question": "<질문>",
         "sub_questions": ["...", "..."],
         "conclusion": "<예/아니오 — 한 줄 이유. 판단형이 아니면 null>",
         "fact":   {"answer": "...", "evidence": ["app/main.py:42"]},
         "reason": {"answer": "... (근거 출처: 담당자 합의 | 요구사항 | 내 판단 | 기술 제약)", "evidence": ["DECISIONS.md:#D3"]},
         "impact": {"answer": "...", "evidence": ["..."]},
         "plan":   {"answer": "유지/바꿀 것 + 확인 방법(입력 → 기대 결과)", "evidence": ["..."]},
         "optional_cells": ["reason"],
         "must_mention": ["<채점 때 꼭 나와야 할 숫자·함수명·화면 문구 1~3개>"]
       }
     ]
   }
   optional_cells에는 answer-frame.md에서 그 유형이 "—"인 칸을 넣는다. 그 칸도 답은 채워 둔다(해설용).

마지막 응답에는 "작성 완료, 문항 수 N, 유형 분포"만 쓴다. 질문과 답 내용은 응답에 쓰지 않는다.
```
